An agent credential lets an AI agent act on exactly one store, in exactly one mode, within an explicit set of scopes. It is a separate credential type from [API keys](/authentication) and OAuth tokens: only `spa_` tokens are accepted on `/api/v2/agentic/*`, and only on those endpoints. An API key sent to an agentic endpoint is rejected, and an agent credential sent to `/api/v2/payments` is rejected.

## Token format

```text
spa_live_<48 hex characters>
spa_test_<48 hex characters>
```

The prefix carries the mode. There is no `X-Livemode` header on the agentic API and no way to switch a credential between modes after creation.

SouthPay stores a SHA-256 digest plus the first 16 characters for display. The full token is returned once, at creation, and cannot be recovered afterwards — if you lose it, revoke the credential and create another.

Agents send a standard bearer header on every request:

```bash
curl https://api.southpay.io/api/v2/agentic/account \
  -H "Authorization: Bearer spa_test_..."
```

A missing or malformed token returns `401` with code `agent_credential_required`. A token matching no active credential returns `401` with code `invalid_agent_credential`. Revoked and expired credentials stop working immediately.

## Scopes

| Scope | Grants |
| --- | --- |
| `payments:read` | Read payments and refunds |
| `payments:write` | Create and cancel payments, request refunds |
| `payouts:read` | Read payouts |
| `payouts:write` | Create payouts |
| `assets:read` | Read accepted tokens, balances, payout limits, exchange rates |
| `assets:write` | Enable or disable accepted tokens |
| `x402:read` | Read session mandates and x402 settlements |
| `x402:write` | Issue mandates, create x402 settlements |

Omitting scopes at creation grants all eight. Pass an explicit list for least privilege. A call outside the credential's scopes returns `403` with code `insufficient_scope`.

Scopes are independent, not hierarchical: a credential with `payments:write` still needs `payments:read` to list payments.

<Note>
  A scope is necessary but not sufficient for money movement. Refunds, token changes, payouts and mandate issuance are additionally gated, and deny by default. See [agent authorization](/agentic/authorization).
</Note>

## Creating a credential

There are two paths, and neither uses an API key.

### In the dashboard

Open **Agents** and create a credential, choosing the mode, a name, a principal for the audit trail, the scopes and an optional expiry. The full token is shown once. The same screen lists, revokes and shows per-credential activity, and is where you configure [spend limits](#spend-limits).

The endpoints behind those screens accept dashboard sessions only. They are not part of the public API, so there is no API-key or OAuth-token equivalent for creating, listing or revoking credentials — including for a platform acting on a sub-merchant, which is refused with `403 platform_cannot_issue_credentials`.

### Minting a credential from an OAuth token

If you are building an application that connects to merchant stores, exchange a user-consented OAuth access token for an agent credential. This is the public endpoint the [MCP server's browser login](/agentic/mcp-server#browser-login-oauth) uses.

The access token must hold the `agents:write` scope and must be bound to a store.

<CodeGroup>
```bash Request
curl -X POST https://api.southpay.io/api/v2/oauth/agent_credentials \
  -H "Authorization: Bearer spo_..." \
  -H "Content-Type: application/json" \
  -d '{"scopes": ["payments:read", "payments:write"]}'
```

```json Response 201
{
  "id": "9f1c0f3a-6d52-4a71-b0c8-3e5d9a2b7c14",
  "token_prefix": "spa_test_4f6a9c1e",
  "mode": "test",
  "livemode": false,
  "name": "Acme Agent (merchant@example.com)",
  "agent_principal": "oauth:spo_app_acme:1c8f...",
  "scopes": ["payments:read", "payments:write"],
  "last_used_at": null,
  "revoked_at": null,
  "expires_at": null,
  "created_at": "2026-07-12T12:00:00.000Z",
  "secret": "spa_test_4f6a9c1e..."
}
```
</CodeGroup>

Details that matter:

- The credential's mode follows the OAuth grant's `livemode`, not a parameter.
- `scopes` is optional. Unknown values are dropped, and an empty or absent list falls back to the default scopes.
- The `agent_principal` is derived as `oauth:{client_id}:{user_id}`, so exactly **one credential exists per application, user, store and mode**. Calling this endpoint again for the same combination **rotates the existing credential** rather than creating a second one. Any key issued by an earlier call stops working at that moment.
- `secret` is the full token, present only on this response.

Failures: `403 insufficient_scope` if the token lacks `agents:write`, `422 store_required` if the token is not bound to a store.

<Warning>
  `secret` is shown once. Store it in a secrets manager. If it leaks, revoke the credential from the dashboard — there is no way to read it back.
</Warning>

## Spend limits

Spend limits are per-credential, per-asset payout caps set by the merchant in the dashboard. They do two jobs:

1. **They unlock payouts.** Without an authorization provider, an agent cannot pay out an asset at all until a spend limit exists for it. The attempt is refused with `403 payout_controls_required` before any balance check runs.
2. **They cap payouts.** Each payout is checked against a per-transaction cap and a daily counter that resets at midnight UTC, returning `403 per_tx_cap_exceeded` or `403 daily_cap_exceeded`.

Caps are atomic units of the asset. USDC has 6 decimals, so `50000000` is 50 USDC. Either cap can be left unset, and a limit with only a daily cap still unlocks the asset.

An agent inspects its own headroom with `GET /api/v2/agentic/payout_limits`, or the `get_payout_limits` MCP tool:

```json Response 200
{
  "limits": [
    {
      "asset_id": "ETH_USDC",
      "coin_symbol": "USDC",
      "chain_symbol": "ETH",
      "atomic_decimals": 6,
      "per_tx_cap_atomic": "50000000",
      "daily_cap_atomic": "200000000",
      "daily_spent_atomic": "35000000",
      "daily_remaining_atomic": "165000000",
      "controls_configured": true
    }
  ],
  "utc_day": "2026-07-12"
}
```

`controls_configured: false` on an asset predicts a `payout_controls_required` denial. Size payouts from this endpoint rather than discovering caps through a `403`.

## Activity and audit

Every payment, payout, refund and x402 settlement records the credential that created it, and agentic queries are filtered by that credential — so an agent sees only its own records, even on a store with several agents. Merchants review per-credential activity in the dashboard under **Agents**.

## Rate limiting

Agentic endpoints allow **120 requests per minute per credential**. Over the limit, requests return `429`:

```json Response 429
{
  "error": {
    "message": "Too many requests",
    "code": "rate_limited"
  }
}
```

No `Retry-After` header is set. `GET /api/v2/agentic/market_data` is outside this limit: it is unauthenticated and throttled at 30 requests per minute per IP.
