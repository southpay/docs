title: "Refunds"
description: "Return crypto to the customer for a completed, failed, or expired payment intent, in full or in part."
sidebarTitle: "Refunds"
---

<Warning>
  All endpoints require authentication. See [Authentication](/authentication).
</Warning>

Base URL: `https://api.southpay.io/api/v2`

A refund returns funds on-chain to the address the customer paid from. Refunds are scoped to a payment intent. A single refund request can produce more than one refund record when the original payment arrived across multiple assets or addresses, so both endpoints return an array.

Amounts are expressed in **atomic units** of the asset. Convert with `decimal = atomic / 10^atomic_decimals`.

A refund can be created in two ways:

- **Automatic.** When a payment is rejected (overpaid on a store that does not accept overpayments, or underpaid past expiration on a store that does not accept underpayments), Southpay initiates a full refund of the confirmed funds. These carry a `reason` of `failed_overpaid` or `failed_underpaid`.
- **Requested.** You call the create endpoint below. These carry a `reason` of `merchant_requested`.

---

## Refund lifecycle

| Status | Terminal | Description |
| --- | --- | --- |
| `pending` | No | Refund created, queued for execution. |
| `submitted` | No | Broadcast to the network, awaiting confirmation. |
| `confirmed` | Yes | On-chain confirmations met. |
| `failed` | Yes | The refund could not be completed. |

When a refund reaches `confirmed`, its payment intent transitions to `refunded` with `state_reason: refund_completed`.

### `reason`

| Reason | Set when |
| --- | --- |
| `merchant_requested` | You requested the refund through the API. |
| `failed_underpaid` | Automatic refund of an underpaid payment the store does not accept. |
| `failed_overpaid` | Automatic refund of an overpaid payment the store does not accept. |

## Request a refund

Requires an `Idempotency-Key` header. Retrying with the same key returns the original refund instead of creating a duplicate.

An intent is refundable through this endpoint while its status is `completed`, `failed`, or `expired` and it still has confirmed funds that have not already been refunded.

Omit `amount` to refund the full remaining amount. Provide `amount` (decimal) to refund a partial amount. Provide `asset_id` when the intent received more than one asset and you want to refund a specific one.

By default the refund is sent to the address the customer paid from. Provide `destination_address` to send it somewhere else, typically when the customer paid from an exchange or custodial wallet and has supplied a wallet address they control. The override must be a valid address for the asset's chain and must not be a Southpay deposit address. If an automatic refund has already `failed`, requesting a refund with a `destination_address` creates a fresh attempt to the new address; while a refund is `pending` or `submitted`, requests return the existing refund instead of creating a second one.

<Note>
  Partial refunds (`amount`) and `asset_id` selection apply only to `completed` intents. For `failed` or `expired` intents the endpoint always refunds the full confirmed balance across every asset; sending `amount` on those returns `422`.
</Note>

<Warning>
  On-chain transfers are irreversible. Double-check a `destination_address` before sending: funds sent to a wrong address cannot be recovered.
</Warning>

<CodeGroup>
```bash Request
POST /payments/:payment_intent_id/refunds
Authorization: Bearer <API_KEY>
Idempotency-Key: refund_order_123
Content-Type: application/json

{
  "refund": {
    "amount": "10.00",
    "asset_id": "ETH_USDC"
  }
}
```

```json Response 201
[
  {
    "id": "01HZ...",
    "status": "pending",
    "reason": "merchant_requested",
    "destination_address": "0xabc...",
    "amount_atomic": "10000000",
    "tx_hash": null,
    "attempts": 0,
    "asset_id": "ETH_USDC",
    "coin_symbol": "USDC",
    "chain_symbol": "ETH",
    "atomic_decimals": 6,
    "created_at": "2026-05-12T12:00:00.000Z",
    "updated_at": "2026-05-12T12:00:00.000Z"
  }
]
```
</CodeGroup>

**Request fields**

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `refund[amount]` | string | No | Decimal amount to refund. Defaults to the full received amount. |
| `refund[asset_id]` | string | No | Restrict the refund to one asset when the intent received several. |
| `refund[destination_address]` | string | No | Send the refund to this address instead of the address the customer paid from. Must be valid for the asset's chain. |
| `Idempotency-Key` | header | Yes | Missing key returns `422`. |

**Common errors**

All error responses use status `422` with an `{ "error": "..." }` body.

| Condition | Notes |
| --- | --- |
| Missing `Idempotency-Key` header | Header is required. |
| Intent status is not `completed`, `failed`, or `expired` | `NotRefundableError`. |
| No confirmed funds available to refund | `NothingToRefundError`. |
| `amount` sent for a `failed` or `expired` intent | Partial refunds are only supported for completed payments. |
| `amount` is not a valid number, or is not positive and within the refundable balance | `InvalidAmountError`. |
| `asset_id` does not match any confirmed payment on the intent | `AssetNotFoundError`. |
| Partial refund requested without `asset_id` when the intent has confirmed funds in multiple assets | `AmbiguousAssetError`. |
| `destination_address` sent without `asset_id` when the intent has confirmed funds in multiple assets | `AmbiguousAssetError`. |
| The source address on the confirmed transaction is missing or fails format validation | `InvalidDestinationError`. |
| `destination_address` fails format validation for the asset's chain, or is a Southpay deposit address | `InvalidDestinationError`. |
| Refund exceeds the merchant's available ledger balance for the asset | `InsufficientBalanceError`. |

<Tip>
  Subscribe to the `payment_intent.refunded` [webhook event](/webhooks) instead of polling for refund status.
</Tip>
