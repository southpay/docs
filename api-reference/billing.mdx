<Warning>
  Billing is a gated feature. Customers and invoices require billing to be enabled on your store; products, prices, and subscriptions additionally return `403` (`"Billing is not enabled for this store"`) when the flag is off. Contact support to enable it. All endpoints require authentication; see [Authentication](/authentication).
</Warning>

Base URL: `https://api.southpay.io/api/v2/billing`

Billing builds on the same crypto checkout used for one-off [payment intents](/api-reference/payments). An invoice generates a hosted payment page; a subscription issues invoices automatically each cycle. Money amounts are in **cents** of the stated `currency`.

This page documents the resource shapes and the available operations. Subscribe to the [billing webhook events](/webhooks#billing-events) (`subscription.created`, `subscription.updated`, `subscription.past_due`, `subscription.canceled`, `invoice.finalized`, `invoice.paid`, `invoice.voided`) rather than polling. Each subscription renewal generates an invoice, so `invoice.finalized` and `invoice.paid` are your renewal and payment signals.

## Customers

A customer is the billed party. Email is unique per store.

```bash
GET    /billing/customers        # list (q, page, per_page)
POST   /billing/customers        # create
GET    /billing/customers/:id    # read
PATCH  /billing/customers/:id    # update
DELETE /billing/customers/:id    # soft-delete
```

<CodeGroup>
```bash Create
POST /billing/customers
Authorization: Bearer <API_KEY>
Content-Type: application/json

{
  "customer": {
    "email": "ada@example.com",
    "name": "Ada Lovelace",
    "phone": "+15551234567",
    "billing_address": { "line1": "1 Analytical Way", "city": "London", "country": "GB" },
    "metadata": { "crm_id": "c_123" }
  }
}
```

```json Response 201
{
  "id": "01J0...",
  "email": "ada@example.com",
  "name": "Ada Lovelace",
  "phone": "+15551234567",
  "billing_address": { "line1": "1 Analytical Way", "city": "London", "country": "GB" },
  "metadata": { "crm_id": "c_123" },
  "created_at": "2026-05-12T12:00:00.000Z",
  "updated_at": "2026-05-12T12:00:00.000Z"
}
```
</CodeGroup>

| Field | Required | Description |
| --- | --- | --- |
| `customer[email]` | Yes | Unique per store. A duplicate returns `409`. |
| `customer[name]` | No | Display name. |
| `customer[phone]` | No | Contact phone. |
| `customer[billing_address]` | No | Free-form address object. |
| `customer[metadata]` | No | Arbitrary key-value pairs. |

The list endpoint accepts `q` (matches email or name), `page`, and `per_page` (default 25, max 100).

## Products and prices

A product is a sellable thing; a price attaches an amount, currency, and billing interval to it. Prices are immutable once created (you archive and replace rather than edit). Products and prices are gated behind the billing feature flag.

```bash
GET   /billing/products                       # list
POST  /billing/products                        # create
GET   /billing/products/:id                    # read (includes prices)
PATCH /billing/products/:id                    # update

GET   /billing/products/:product_id/prices     # list
POST  /billing/products/:product_id/prices     # create
GET   /billing/products/:product_id/prices/:id # read
POST  /billing/products/:product_id/prices/:id/archive
POST  /billing/products/:product_id/prices/:id/activate
```

A price has `unit_amount_cents`, `currency`, `interval` (one of `daily`, `weekly`, `monthly`, `yearly`), `interval_count`, and `active`. Set `interval_count` to bill every N intervals — for example `interval: "monthly"` with `interval_count: 3` is quarterly. Money fields (`unit_amount_cents`, `currency`, `interval`, `interval_count`) are immutable once the price exists; archive and create a new price to change them.

```json Price
{
  "id": "01J2...",
  "product_id": "01JP...",
  "unit_amount_cents": 2900,
  "currency": "USD",
  "interval": "monthly",
  "interval_count": 1,
  "active": true,
  "metadata": {},
  "created_at": "2026-05-12T12:00:00.000Z",
  "updated_at": "2026-05-12T12:00:00.000Z"
}
```

## Invoices

An invoice is a set of line items billed to a customer. Create it as a draft, add line items, then `finalize` to lock it and generate the hosted payment page (`public_token`). `void` cancels an unpaid invoice.

```bash
GET   /billing/invoices             # list (status, customer_id, subscription_id, page, per_page)
POST  /billing/invoices             # create draft
GET   /billing/invoices/:id         # read (includes line_items, customer)
PATCH /billing/invoices/:id         # update draft (incl. line_items)
POST  /billing/invoices/:id/finalize
POST  /billing/invoices/:id/void
```

<CodeGroup>
```bash Create draft
POST /billing/invoices
Authorization: Bearer <API_KEY>
Content-Type: application/json

{
  "invoice": {
    "customer_id": "01J0...",
    "currency": "USD",
    "due_at": "2026-06-01T00:00:00Z",
    "description": "May usage",
    "metadata": {}
  }
}
```

```json Response 201
{
  "id": "01J1...",
  "customer_id": "01J0...",
  "subscription_id": null,
  "number": null,
  "status": "draft",
  "currency": "USD",
  "public_token": null,
  "subtotal_cents": 0,
  "total_cents": 0,
  "due_at": "2026-06-01T00:00:00.000Z",
  "description": "May usage",
  "metadata": {},
  "finalized_at": null,
  "voided_at": null,
  "paid_at": null,
  "created_at": "2026-05-12T12:00:00.000Z",
  "updated_at": "2026-05-12T12:00:00.000Z"
}
```
</CodeGroup>

Line items are set on `PATCH` via `invoice[line_items][]` with `description`, `quantity`, and `unit_amount_cents`. After `finalize`, the response includes a `public_token`; the hosted payment page lives at `/api/v2/billing/invoice/:token`.

## Subscriptions

A subscription bills a customer on a recurring schedule, issuing an invoice each cycle. Subscriptions are gated behind the billing feature flag.

```bash
GET   /billing/subscriptions             # list (status, customer_id, page, per_page)
POST  /billing/subscriptions             # create
GET   /billing/subscriptions/:id         # read (includes items, price, customer)
PATCH /billing/subscriptions/:id         # change plan (replace items/quantities)
POST  /billing/subscriptions/:id/cancel     # cancel now or at period end
POST  /billing/subscriptions/:id/uncancel   # undo a scheduled cancellation
POST  /billing/subscriptions/:id/pause
POST  /billing/subscriptions/:id/resume
```

### Items

A subscription is billed as one or more **items**, each pairing a price with a quantity. The first item is the anchor: its price sets the billing interval and currency for the whole subscription, and is mirrored on the top-level `price_id`/`quantity`. Add more items for a base plan plus add-ons — every item becomes a line on the same cycle invoice.

All items must share the same `interval`, `interval_count`, and `currency`.

A single price serves any number of customers: reuse one `price_id` across many subscriptions, one per customer.

### Create

<CodeGroup>
```bash Create
POST /billing/subscriptions
Authorization: Bearer <API_KEY>
Content-Type: application/json

{
  "subscription": {
    "customer_id": "01J0...",

      { "price_id": "01J2...", "quantity": 1 },
      { "price_id": "01J5...", "quantity": 3 }

```

| Field | Required | Description |
| --- | --- | --- |
| `subscription[customer_id]` | Yes | An existing billing customer. |
| `subscription[items]` | Yes* | Array of `{ price_id, quantity }`. The first item is the anchor. |
| `subscription[price_id]` | Yes* | Shorthand for a single-item subscription. Provide either `items` or `price_id`. |
| `subscription[quantity]` | No | Quantity for the `price_id` shorthand. Defaults to 1. |
| `subscription[trial_period_days]` | No | Days of free trial. No invoice is issued during the trial; the first invoice is generated when it ends. Defaults to 0. |
| `subscription[grace_cycles]` | No | Cycles to allow past-due before the subscription is treated as failed. Defaults to 1. |
| `subscription[metadata]` | No | Arbitrary key-value pairs. |

### Statuses

| Status | Meaning |
| --- | --- |
| `trialing` | In a free trial. Converts to `active` and bills its first cycle at `trial_end`. |
| `active` | Billing normally each cycle. |
| `past_due` | A cycle invoice went unpaid within its grace window. |
| `paused` | Billing suspended. Call `resume` to continue. |
| `canceled` | Ended. Terminal. |

### Change the plan

`PATCH /billing/subscriptions/:id` replaces the subscription's items. Send the full new set of items; the change applies from the next cycle (there is no mid-cycle proration).

```bash
PATCH /billing/subscriptions/01J3...

{ "subscription": { "items": [ { "price_id": "01J9...", "quantity": 2 } ] } }
```

### Cancel

`cancel` ends the subscription immediately. Pass `at_period_end: true` to keep it active until the current period ends and cancel automatically — the response then has `cancel_at_period_end: true` and `cancel_at` set. Call `uncancel` to clear a scheduled cancellation while the subscription is still live.

```bash
POST /billing/subscriptions/01J3.../cancel

{ "at_period_end": true }
```

### Pause and resume

`pause` suspends billing; `resume` restarts it and opens a fresh period from now.

If a cycle invoice goes unpaid, Southpay emits `subscription.past_due`. Once the grace window (roughly `grace_cycles` × the billing interval) is exhausted, the invoice is marked uncollectible and the subscription is canceled for non-payment.
