A payment intent is how you charge a customer. You post a fiat amount, SouthPay locks an exchange rate and allocates one on-chain deposit address per asset your store accepts, and you send the customer to the hosted checkout page. Which assets appear is decided by your store settings, not by anything in the request.

For the walkthrough, see the [payment intents guide](/payment-intents). This page is the field-level reference.

Every path below is relative to `https://api.southpay.io/api/v2`. All amounts you send are fiat major units; all crypto amounts you read back are atomic-unit strings.

## Authentication and scope

Reads require `payments:read`, writes require `payments:write`. A secret API key (`sp_sk_…`), an OAuth token, or a dashboard session all work. A publishable key (`sp_pk_…`) can call `POST /payments` and nothing else. Any other path returns `403` `publishable_key_forbidden`.

## Create a payment intent

**`POST /payments`**. Scope `payments:write`. Publishable keys allowed. `Idempotency-Key` optional.

All fields go inside a required `payment_intent` object.

<ParamField body="payment_intent.amount" type="string" required>
  Fiat amount in major units, as a decimal string (`"49.99"`). Must be greater than zero. Multiplied by 100 and stored as `settlement_amount_cents`.
</ParamField>

<ParamField body="payment_intent.currency" type="string" required>
  Uppercase ISO 4217 code. One of `USD`, `EUR`, `GBP`, `HKD`, `SGD`, `JPY`, `DKK`, `CHF`, `SEK`, `NOK`. This prices the payment; it does not restrict which crypto assets the customer may pay with.
</ParamField>

<ParamField body="payment_intent.success_url" type="string">
  Where checkout sends the customer after a successful payment.
</ParamField>

<ParamField body="payment_intent.failed_url" type="string">
  Where checkout sends the customer after a failure or expiry.
</ParamField>

<ParamField body="payment_intent.order_id" type="string">
  Your own order reference. Maximum 255 characters. Filterable on the list endpoint.
</ParamField>

<ParamField body="payment_intent.title" type="string">
  Short label shown on the checkout page. Maximum 150 characters.
</ParamField>

<ParamField body="payment_intent.description" type="string">
  Longer description shown on the checkout page. Maximum 500 characters.
</ParamField>

<ParamField body="payment_intent.image_url" type="string">
  Product or order image shown on checkout. Must be `https` and at most 2048 characters. Surfaces as `display_image_url` on the detail view.
</ParamField>

<ParamField body="payment_intent.metadata" type="object">
  Key-value pairs echoed back on the intent and in every payment webhook. At most 50 keys, and **every value must be a string**. Numbers and booleans are rejected.
</ParamField>

<ParamField body="payment_intent.line_items" type="object[]">
  Order breakdown shown on checkout. At most 50 items.

  <Expandable title="line item properties">
    <ParamField body="description" type="string" required>
      Maximum 255 characters.
    </ParamField>
    <ParamField body="quantity" type="integer" required>
      Must be a positive integer.
    </ParamField>
    <ParamField body="unit_amount_cents" type="integer" required>
      Minor units of `currency`. Must be a non-negative integer.
    </ParamField>
    <ParamField body="image_url" type="string">
      Must be `https`.
    </ParamField>
  </Expandable>
</ParamField>

### Response fields

<ResponseField name="id" type="string" required>
  Bare UUID. There is no prefixed-id scheme anywhere in this API.
</ResponseField>

<ResponseField name="reference" type="string" required>
  16 uppercase alphanumeric characters. This is the checkout token and the value that appears as `data.object.id` in webhooks.
</ResponseField>

<ResponseField name="hosted_url" type="string">
  The customer-facing checkout page.
</ResponseField>

<ResponseField name="status" type="string" required>
  One of `pending`, `processing`, `completed`, `expired`, `failed`, `refunded`. See [lifecycle](#lifecycle).
</ResponseField>

<ResponseField name="state_reason" type="string | null">
  Why the intent reached its current status. See [payment lifecycle](/payment-lifecycle#state-reasons).
</ResponseField>

<ResponseField name="settlement_amount" type="string" required>
  Fiat amount as a string with exactly two decimals, for example `"49.99"`. Note that the webhook envelope carries `settlement_amount_cents` as an integer instead.
</ResponseField>

<ResponseField name="settlement_currency" type="string" required>
  The fiat currency the intent is priced in.
</ResponseField>

<ResponseField name="terminal" type="boolean" required>
  True when `status` is `completed`, `expired`, `refunded` or `failed`. The intent will not change again.
</ResponseField>

<ResponseField name="expires_at" type="string" required>
  ISO 8601. Always 60 minutes after `created_at`.
</ResponseField>

<ResponseField name="settlement_status" type="string | null">
  The underlying settlement record: `pending`, `processing`, `completed`, `failed`, or `null`. It is never `"settled"`.
</ResponseField>

<ResponseField name="auto_swap_status" type="string | null">
  `completed`, `pending`, `failed`, `skipped`, or `null` when no auto-swap applies.
</ResponseField>

<ResponseField name="reconciliation_status" type="string | null">
  Status of the most recent reconciliation snapshot. See [Reconciliation](/api-reference/reconciliation).
</ResponseField>

<ResponseField name="payment_addresses" type="object[]">
  One deposit address per asset your store accepts. Returned by create and retrieve.

  <Expandable title="properties">
    <ResponseField name="id" type="string">Address record UUID.</ResponseField>
    <ResponseField name="address" type="string">The on-chain deposit address. Send funds here.</ResponseField>
    <ResponseField name="status" type="string">`pending` or `confirmed`.</ResponseField>
    <ResponseField name="crypto_amount_atomic" type="string">Exact amount to send, in atomic units of the asset.</ResponseField>
    <ResponseField name="exchange_rate_snapshot" type="string">
      The locked rate as a plain decimal string, for example `"2217.000000000000000000"`. It is a number, not an object.
    </ResponseField>
    <ResponseField name="supported_asset" type="object">
      `asset_id`, `coin_symbol`, `chain_symbol`, `token_standard`, `settlement_currency`, `atomic_decimals`, `min_withdrawal_atomic`, `chain_name`, `network`, `fiat_eligible`.
    </ResponseField>
  </Expandable>
</ResponseField>

### Create errors

Validation failures on this endpoint return `422` with the flat envelope `{"error": "<message>"}`.

| Message | Cause |
| --- | --- |
| `amount is required and must be positive` | `amount` missing or blank. |
| `amount must be positive` | `amount` rounds to zero or below. |
| `title must be at most 150 characters` | Over the limit. |
| `description must be at most 500 characters` | Over the limit. |
| `order_id must be at most 255 characters` | Over the limit. |
| `image_url must be a valid https URL` | Not `https`, no host, or over 2048 characters. |
| `line_items must be an array` | Sent as an object or scalar. |
| `line_items must have at most 50 items` | Over the limit. |
| `each line item requires a description` | Blank `description`. |
| `line item quantity must be a positive integer` | Zero, negative or non-integer. |
| `line item unit_amount_cents must be a non-negative integer` | Negative or non-integer. |
| `metadata must have at most 50 keys` | Over the limit. |
| `metadata values must be strings` | A value was a number, boolean or nested object. |

An unsupported `currency` also returns `422`, but through the global handler, so it uses the *structured* envelope: `{"error": {"message": "Unsupported settlement currency: XYZ", "code": null}}`. Write your client to handle both shapes.

<Note>
Omitting `currency` entirely, or omitting the `payment_intent` wrapper, currently returns `500` rather than a validation error. Always send both.
</Note>

`POST /payments` is rate limited to 120 requests per minute, keyed on your credential. Over the limit you get `429` with `{"error": "Too many requests. Please try again later."}` and no `Retry-After` header. See [Rate limits](/rate-limits) for every throttled path.

### Detail-only fields

<ResponseField name="checkout_url" type="string">
  The API-hosted checkout endpoint, `https://api.southpay.io/api/v2/checkout/{reference}`. Distinct from `hosted_url`, which is the customer-facing page.
</ResponseField>

<ResponseField name="display_image_url" type="string | null">
  The `image_url` you supplied on create.
</ResponseField>

<ResponseField name="line_items" type="object[] | null">
  The line items you supplied on create.
</ResponseField>

<ResponseField name="amount_paid" type="string">
  Fiat value of confirmed funds, two decimals. `"0.00"` when nothing has confirmed.
</ResponseField>

<ResponseField name="paid_at" type="string | null">
  Timestamp of the transition into `completed`, falling back to the last transition.
</ResponseField>

<ResponseField name="customer_pays_fee" type="boolean">
  When true the customer was charged the SouthPay fee on top of the order amount.
</ResponseField>

  </Expandable>
</ResponseField>

<ResponseField name="financials" type="object | null">
  Ledger-derived fiat view. Null until crypto is received.

    <ResponseField name="gross_amount" type="string">Two decimals.</ResponseField>

    <ResponseField name="net_amount" type="string">Gross minus fee.</ResponseField>
    <ResponseField name="fee_percentage" type="string">Percentage points (`"1.00"` is 1%), unlike `fee.fee_percentage`.</ResponseField>
    <ResponseField name="currency" type="string">Settlement currency.</ResponseField>
    <ResponseField name="asset_id" type="string">Asset received.</ResponseField>
    <ResponseField name="exchange_rate" type="string | null">Rate applied.</ResponseField>

  <Expandable title="properties">
    <ResponseField name="tx_hash" type="string">On-chain hash.</ResponseField>
    <ResponseField name="from_address" type="string | null">Sender, used as the default refund destination.</ResponseField>
    <ResponseField name="deposit_address" type="string | null">The SouthPay address that received the funds.</ResponseField>
    <ResponseField name="confirmations" type="integer">Confirmations seen so far.</ResponseField>

    <ResponseField name="network" type="string | null">For example `ethereum`.</ResponseField>

  </Expandable>
</ResponseField>

  <Expandable title="properties">
    <ResponseField name="required_atomic" type="string">Amount the intent asked for.</ResponseField>
    <ResponseField name="received_atomic" type="string">Amount confirmed.</ResponseField>
    <ResponseField name="excess_atomic" type="string">Received minus required, floored at `"0"`.</ResponseField>

    <ResponseField name="coin_symbol" type="string" />
    <ResponseField name="atomic_decimals" type="integer" />

<ResponseField name="merchant" type="object">

<ResponseField name="onramp_session" type="object | null">

</ResponseField>

<ResponseField name="onramp_unavailable" type="object | null">
  Why an onramp session could not be offered. Always null once a session exists.
</ResponseField>

<ResponseField name="auto_swap_detail" type="object | null">
  Populated only when an auto-swap has moved past `pending` and has not failed. Keys: `status`, `sell_amount`, `sell_coin_symbol`, `sell_chain_symbol`, `buy_amount`, `buy_coin_symbol`, `buy_chain_symbol`, `estimated`, `expected_buy_amount`, `actual_buy_amount`, `slippage_bps`.
</ResponseField>

<ResponseField name="payment_events" type="object[]">
  Same rows as the [events endpoint](#list-payment-events): `id`, `event_type`, `from_status`, `to_status`, `payload`, `created_at`.

<ResponseField name="timeline" type="object[]">

</ResponseField>

## List payment intents

**`GET /payments`**. Scope `payments:read`.

Returns the list view: the create fields plus `settlement_status` and `auto_swap_status`, without `payment_addresses`. Ordered newest first.

<ParamField query="status" type="string">
  Filter by status. Unrecognized values are ignored rather than rejected.
</ParamField>

<ParamField query="q" type="string">
  Case-insensitive substring match on `reference`.
</ParamField>

<ParamField query="order_id" type="string">
  Exact match on the `order_id` you set at create time.
</ParamField>

<ParamField query="from" type="string">
  ISO date. Includes intents created on or after this day.
</ParamField>

<ParamField query="to" type="string">
  ISO date. Includes intents created up to and including this day.
</ParamField>

<ParamField query="page" type="integer" default="1" />

<ParamField query="per_page" type="integer" default="10">
  Between 1 and 100.
</ParamField>

<CodeGroup>
```bash Request
curl "https://api.southpay.io/api/v2/payments?status=completed&per_page=25" \
```

<Warning>
`status=confirming` is accepted by the filter but `confirming` is not a payment intent status. It always matches zero rows. `confirming` exists only as a *transaction* status inside the `transaction` object. Do not use it as a filter.
</Warning>

<Note>
Pagination is not uniform across this API. Payments, billing, agentic payments and platform endpoints wrap the page in `meta`. Payouts, agentic payouts, balance swaps and x402 settlements use `pagination` instead. Balances, payout schedules, webhook endpoints, billing products, prices and subscriptions return **bare arrays with no pagination at all**.
</Note>

## Summarize payments

**`GET /payments/summary`**. Scope `payments:read`.

Aggregates order counts, volume and success rate over a date range, bucketed by day. Useful for dashboards; it is not a substitute for [reports](/api-reference/reports), which are ledger-accurate PDFs.

<ParamField query="from" type="string">
  ISO date. Defaults to 29 days before `to`.
</ParamField>

<ParamField query="to" type="string">
  ISO date. Defaults to today.
</ParamField>

A range longer than 366 days is silently clamped to 366, and `from` later than `to` is clamped to `to`. Unparseable dates fall back to the defaults instead of erroring.

<CodeGroup>
```bash Request
curl "https://api.southpay.io/api/v2/payments/summary?from=2026-04-01&to=2026-04-07" \
  -H "Authorization: Bearer sp_sk_test_…"
```


## List payment events

**`GET /payments/{payment_intent_id}/events`**. Scope `payments:read`.

The immutable transition log behind your webhook deliveries. Use it to backfill history or to reconcile after a webhook outage. Returns a **bare array**, oldest first, with no pagination.

## Download the invoice PDF

**`GET /payments/{id}/invoice`**. Scope `payments:read`.

Returns `application/pdf` as an attachment named `invoice-{reference}.pdf`. There is no JSON variant, and no status check. An unpaid intent still renders. The only failure is `404` for an unknown id.

```bash Request
curl https://api.southpay.io/api/v2/payments/7b1f0c2e-2b0a-4c31-9f0e-1d2c3b4a5e6f/invoice \
  -H "Authorization: Bearer sp_sk_test_…" \
  -o invoice.pdf
```

## Lifecycle

The `status` field has exactly six values. There is no `created`, no `confirming` and no `overpaid`.

| Status | Terminal | Meaning |
| --- | --- | --- |
| `pending` | No | Created, waiting for the customer to send funds. |
| `processing` | No | Funds detected on-chain, confirmations in progress. |
| `completed` | Yes | Required funds received and confirmed. |
| `expired` | Yes | The 60-minute window elapsed, or an agent canceled the intent. |
| `failed` | Yes | The payment could not be accepted. |
| `refunded` | Yes | Funds were returned to the customer. |

An overpayment is not a separate status: it is `status: "completed"` with `state_reason: "completed_overpaid"`, and the excess is in the `overpayment` object.

For the allowed transitions, all ten `state_reason` values and how statuses map to webhook events, see [payment lifecycle](/payment-lifecycle).
