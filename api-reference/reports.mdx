Reports are PDFs covering a closed date range, generated from the ledger. Two types exist:

- `accounting_transactions` — a ledger-level listing of every entry in the period.
- `merchant_statement` — a summarized statement for the period.

Generation is asynchronous and cached. The first request for a given type, range and currency queues a job and returns `202`. Once the job finishes, the same request returns `200` with a download link. Repeating the request reuses the existing report rather than regenerating it.

Paths are relative to `https://api.southpay.io/api/v2`.

## Authentication and scope

Reports map to the `balances` resource, so `GET` requires **`balances:read`** — not a `reports` scope, which does not exist. Publishable keys are rejected.

## Data availability

Reports only cover days that have fully closed. The latest available date is:

- **Yesterday**, once the current UTC day has passed 12:00.
- **The day before yesterday**, before 12:00 UTC.

Read the current boundary from `available_through` on the [index endpoint](#list-recent-reports) rather than computing it yourself.

## Request a report

**`GET /reports/accounting_transactions`** and **`GET /reports/merchant_statement`** — scope `balances:read`.

Both take the same parameters and return the same body shapes.

<ParamField query="start_date" type="string" required>
  ISO date, inclusive. Missing or unparseable dates currently produce `500` rather than a validation error, so send a well-formed value.
</ParamField>

<ParamField query="end_date" type="string" required>
  ISO date, inclusive. Must be on or after `start_date` and no later than `available_through`.
</ParamField>

<ParamField query="currency" type="string">
  Restrict to one settlement currency: `USD`, `EUR`, `GBP`, `HKD`, `SGD`, `JPY`, `DKK`, `CHF`, `SEK` or `NOK`. Anything else is ignored and the report covers all currencies.
</ParamField>

The maximum range is 366 days.

<CodeGroup>
```bash Request
curl "https://api.southpay.io/api/v2/reports/accounting_transactions?start_date=2026-04-01&end_date=2026-04-30&currency=EUR" \
  -H "Authorization: Bearer sp_sk_live_…"
```

```json Response 202
{
  "status": "pending",
  "report_id": 4821
}
```

```json Response 200
{
  "status": "generated",
  "url": "https://<presigned-host>/accounting_transactions/2026-04-01_2026-04-30_EUR.pdf?…",
  "expires_in": 3600
}
```
</CodeGroup>

### Polling

Poll the same URL with the same parameters. The status code tells you where you are.

| Report status | HTTP | Body |
| --- | --- | --- |
| `pending` | **202** | `{"status": "pending", "report_id": 4821}` |
| `generated` | 200 | `{"status": "generated", "url": "…", "expires_in": 3600}` |
| `no_data` | 422 | `{"status": "no_data", "error": "No transactions found for the selected period and filters."}` |
| `failed` | 422 | `{"status": "failed", "report_id": 4821, "error": "…"}` |

Treat `202` as "not ready, try again", not as success. A few seconds between polls is enough for typical ranges.

A `failed` report is retried automatically on your next request. So is a `pending` report that has not been touched in five minutes, which recovers a job that died mid-run.

<ResponseField name="url" type="string">
  A presigned download link, valid for `expires_in` seconds.
</ResponseField>

<ResponseField name="expires_in" type="integer">
  Always 3600. Fetch the PDF promptly, or re-request the report to mint a fresh link.
</ResponseField>

<ResponseField name="report_id" type="integer">
  The report record's id. Also appears in the index listing.
</ResponseField>

<Note>
`url` is a time-limited presigned download link. Treat it as opaque: follow it exactly as returned, query string included. The host is not a `southpay.io` domain, and neither the hostname nor the path shape is stable, so do not allowlist a hostname, parse the URL, or try to reconstruct it.
</Note>

## List recent reports

**`GET /reports`** — scope `balances:read`. No parameters.

Returns the 50 most recent reports for the store, newest first, plus the current availability boundary.

<CodeGroup>
```bash Request
curl https://api.southpay.io/api/v2/reports \
  -H "Authorization: Bearer sp_sk_live_…"
```

```json Response 200
{
  "reports": [
    {
      "id": 4821,
      "report_type": "accounting_transactions",
      "status": "generated",
      "period_from": "2026-04-01",
      "period_to": "2026-04-30",
      "currency": "EUR",
      "generated_at": "2026-05-02T08:14:33.000Z",
      "error": null,
      "url": "https://<presigned-host>/accounting_transactions/2026-04-01_2026-04-30_EUR.pdf?…",
      "expires_in": 3600
    },
    {
      "id": 4790,
      "report_type": "merchant_statement",
      "status": "pending",
      "period_from": "2026-05-01",
      "period_to": "2026-05-10",
      "currency": null,
      "generated_at": null,
      "error": null
    }
  ],
  "available_through": "2026-05-11"
}
```
</CodeGroup>

<ResponseField name="reports" type="object[]" required>
  <Expandable title="properties">
    <ResponseField name="id" type="integer">Report id. An integer, not a UUID — reports are the exception in this API.</ResponseField>
    <ResponseField name="report_type" type="string">`accounting_transactions` or `merchant_statement`.</ResponseField>
    <ResponseField name="status" type="string">`pending`, `generated`, `failed` or `no_data`.</ResponseField>
    <ResponseField name="period_from" type="string">Start of the covered range.</ResponseField>
    <ResponseField name="period_to" type="string">End of the covered range.</ResponseField>
    <ResponseField name="currency" type="string | null">Null when the report covers all currencies.</ResponseField>
    <ResponseField name="generated_at" type="string | null">Null until generation finishes.</ResponseField>
    <ResponseField name="error" type="string | null">Failure text. Free-form — do not match on it.</ResponseField>
    <ResponseField name="url" type="string">Presigned link. Present only when `status` is `generated`.</ResponseField>
    <ResponseField name="expires_in" type="integer">Present only alongside `url`.</ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="available_through" type="string" required>
  The latest date a report may end on, as of now. Use it to build a valid `end_date`.
</ResponseField>

Reports are cached per store, type, date range and currency. Requesting the same combination twice returns the same record — there is no way to force regeneration other than changing a parameter.

## Errors

Pre-flight validation returns `422`, but the `error` value is inconsistent: one is prose, the other two are machine codes carrying an extra field.

| Status | Body | Cause |
| --- | --- | --- |
| `422` | `{"error": "start_date must be on or before end_date"}` | Dates reversed. |
| `422` | `{"error": "date_range_too_large", "max_days": 366}` | Range exceeds 366 days. |
| `422` | `{"error": "date_range_unavailable", "available_through": "2026-05-11"}` | `end_date` is past the boundary. Retry with the returned date. |
| `403` | `{"error": {"message": "Insufficient scope: balances:read required", "code": "insufficient_scope"}}` | Missing scope. |
| `500` | `{"error": {"message": "Internal server error", "code": null}}` | `start_date` or `end_date` missing or unparseable. |

<Note>
Missing or malformed date parameters return `500`, not `422`. Validate the format on your side before calling.
</Note>
