SouthPay is a crypto payment gateway. You charge in fiat; your customer pays in crypto; SouthPay allocates the deposit address, locks the exchange rate, watches the chain for confirmations, credits your balance and pays you out.

There is one object you need to understand: the **payment intent**. You create it with an amount and a currency, and it carries everything else — the deposit addresses, the crypto amounts, the checkout URL, the status.

## The shortest working path

```bash
curl -X POST https://api.southpay.io/api/v2/payments \
  -H "Authorization: Bearer sp_sk_test_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -d '{"payment_intent": {"amount": "49.99", "currency": "USD"}}'
```

The response has a `hosted_url`. Redirect your customer there. When the payment confirms, a signed `payment_intent.completed` webhook arrives at your endpoint and you fulfil the order.

That is the whole integration. The [quickstart](/quickstart) walks the four steps with the real response bodies and a verified webhook handler.

## Three things to know before you build

**The base URL is `https://api.southpay.io` and every path sits under `/api/v2`.** There is no `/v1` and no other version.

**Test and live mode are chosen by the credential, not by the host.** An `sp_sk_test_` key reads and writes test data on the same URL. Test mode has exactly one usable asset, Ethereum Sepolia.

**Errors come back in three different JSON shapes.** `error` is sometimes a string and sometimes an object. Write the parser first — [Errors](/errors) has one you can copy.
