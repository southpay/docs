## Overview

`@southpay/js` renders the Southpay hosted checkout inside your page, either inline or as a modal. It runs in the browser with a [publishable key](/authentication#key-types) (`sp_pk_...`). All payment UI (QR code, wallet connect, status, countdown) lives in a sandboxed iframe served from the checkout origin, so the SDK itself stays small and has no dependencies.

There are two flows:

- **Server-created** - your server creates the payment intent with a secret key, then passes the `reference` to the page and the browser mounts it. The buyer cannot change the amount. Use this for fixed-price goods.
- **Browser-created** - the browser creates the intent with a publishable key. Use this for donations or pay-what-you-want, where a buyer-chosen amount is intended.

<Warning>
  The amount in a browser-created checkout is set on the client and can be altered by the buyer. For fixed prices, create the intent on your server (see [Payment intents](/payment-intents)) and mount the `reference`.
</Warning>

## Install

Load the hosted script, which exposes a global `SouthPay`:

```html
<script src="https://integrate.southpay.io/widgets/v2.js"></script>
```

Or install from npm:

```bash
npm install @southpay/js
```

```ts
import { SouthPay } from "@southpay/js";
```

## Create a client

```ts
const southpay = SouthPay("sp_pk_live_...");
```

`SouthPay()` throws if the value is not a publishable key, so a secret key can never be used by mistake. It returns a client with two resources: `southpay.paymentIntents` (create an intent) and `southpay.checkout` (mount the widget).

| Option | Default | Description |
| --- | --- | --- |
| `apiBase` | `https://api.southpay.io` | API base URL. |
| `checkoutOrigin` | `https://pay.southpay.io` | Origin that serves the checkout iframe. |
| `nonce` | none | CSP nonce. When set, the SDK emits a single nonce'd `<style>` and no inline styles, so it works under a strict `style-src`. |

```ts
const southpay = SouthPay("sp_pk_test_...", {
  apiBase: "http://localhost:3000",
  checkoutOrigin: "http://localhost:5173",
});
```

## Server-created checkout

Create the intent on your server, send the `reference` to the page, then mount it. No key is needed for `mount`.

```ts
southpay.checkout.mount({
  reference: "REFERENCE_FROM_YOUR_SERVER",
  container: "#checkout",
  onCompleted: ({ successUrl }) => {
    if (successUrl) window.location.assign(successUrl);
  },
});
```

## Browser-created checkout

Create the intent with the publishable key, then mount the returned `reference`:

```ts
const { reference } = await southpay.paymentIntents.create({
  amount: "10.00",
  currency: "EUR",
});

southpay.checkout.mount({
  reference,
  container: "#checkout",
  onCompleted: ({ reference }) => console.log("paid", reference),
});
```

`amount` is a decimal string in the major unit of the currency (`"10.00"` is 10 EUR). A `number` is rejected at compile time. Zero-decimal currencies like JPY take whole units (`"1000"`), and the SDK validates the number of decimal places against the currency's ISO-4217 exponent. Omit `container` on `mount` to open the checkout as a modal overlay.

The create request is idempotent: a key is generated per call, or pass your own `idempotencyKey`. It times out after 20 seconds (`timeoutMs`) and accepts an `AbortSignal` via `signal`.

## Options

`checkout.mount` takes a `reference` plus the embed options:

| Option | Type | Description |
| --- | --- | --- |
| `reference` | `string` | The payment intent reference to render. Required. |
| `container` | `string \| HTMLElement` | Element or CSS selector to mount into. Omit for a modal. |
| `minHeight` | `number` | Minimum iframe height in pixels. Defaults to 560. |

It also accepts the [callbacks](#callbacks) below.

`paymentIntents.create` takes `amount` and `currency` (both required) plus the optional `orderId`, `title`, `description`, `imageUrl`, `successUrl`, `failedUrl`, `metadata`, `idempotencyKey`, `signal`, and `timeoutMs`. It returns `{ reference }`.

## Callbacks

| Callback | Payload |
| --- | --- |
| `onReady` | none |
| `onStatusChange` | `{ reference, status }` |
| `onCompleted` | `{ reference, successUrl }` |
| `onFailed` | `{ reference, status }` |
| `onExpired` | `{ reference }` |
| `onError` | `SouthpayError` |

`status` is one of `created`, `pending`, `confirming`, `processing`, `completed`, `failed`, `expired`. When `onCompleted` is not provided, the SDK redirects to `successUrl` if one is present.

`checkout.mount` returns a handle (`paymentIntents.create` returns a `Promise<{ reference }>`):

```ts
const handle = southpay.checkout.mount({ reference, container: "#checkout" });
handle.unmount();
```

## Verify the payment on your server

Southpay sets the payment status from the on-chain payment. As funds arrive and confirm, Southpay moves the intent through `pending → processing → confirming → completed`. You never set the status yourself; you read it.

`onCompleted` runs in the buyer's browser, so use it for the UI only, not to release goods. Before fulfilling, read the status from Southpay:

- listen for the [`payment_intent.completed` webhook](/webhooks), or
- re-fetch the intent with your secret key:

```bash
curl https://api.southpay.io/api/v2/payments/{id} \
  -H "Authorization: Bearer sp_sk_live_..."
```

Fulfill the order only when Southpay reports `status: completed`.

<Warning>
  Never fulfill based on the browser callback alone. A page can call `onCompleted` without a real payment. Southpay marking the intent `completed`, after on-chain confirmation, is the source of truth.
</Warning>

## Errors

`SouthPay()`, `paymentIntents.create`, and `checkout.mount` throw `SouthpayError`, which has a `code`:

| Code | Meaning |
| --- | --- |
| `invalid_publishable_key` | The key is missing or is not a publishable key. |
| `invalid_config` | `apiBase` or `checkoutOrigin` is not a valid http(s) URL. |
| `invalid_amount` | `amount` is not a positive decimal string in major units, or has more decimal places than the currency allows. |
| `missing_currency` | `currency` was not provided. |
| `missing_reference` | `reference` was not provided to `mount`. |
| `container_not_found` | The `container` selector matched no element. |
| `network_error` | The create request failed to reach the API. |
| `timeout` | The create request exceeded `timeoutMs`. |
| `request_failed` | The API returned an error; `message` carries the detail. |
| `invalid_response` | The API response did not include a reference. |
| `widget_load_failed` | The checkout iframe failed to load. |

Use the `isSouthpayError` guard to narrow caught values.

## Security

- The SDK accepts publishable keys only; a secret key throws at construction.
- The checkout runs in a sandboxed iframe. Inbound events are accepted only from the configured `checkoutOrigin` and the checkout window, and every payload is validated.
- Completion redirects are restricted to http(s) URLs.
- For fixed prices, fix the amount on your server and mount the `reference`. Do not rely on a browser-set amount.
