---
title: "Checkout widget"
description: "Embed Southpay hosted checkout in your page with the SouthPay.js browser SDK: init, mount, createCheckout, and the events it emits."
---

SouthPay.js renders Southpay's hosted checkout inside your page, inline or as a modal. All payment UI — QR code, wallet connect, network picker, status, countdown — lives in an iframe served from the checkout origin, so the script itself is a thin DOM shell with no framework and no dependencies.

There are two flows:

- **Server-created** — your server creates the payment intent with a secret key, passes the `reference` to the page, and the browser mounts it. The buyer cannot change the amount. Use this for fixed-price goods.
- **Browser-created** — the browser creates the intent with a publishable key. Use this for donations and pay-what-you-want, where a buyer-chosen amount is the point.

<Warning>
  The amount in a browser-created checkout is set on the client and can be altered by the buyer before the request leaves the page. For fixed prices, create the intent on your server (see [payment intents](/payment-intents)) and mount the returned `reference`.
</Warning>

## Load the script

```html
<script src="https://integrate.southpay.io/widgets/v2.js"></script>
```

The script defines a global `SouthPay` with three functions: `init`, `createCheckout` and `mount`. It is also served from the checkout origin at `https://pay.southpay.io/widgets/v2.js`.

<Note>
  There is no npm package. SouthPay.js ships only as this hosted bundle — load it with a `<script>` tag rather than a bundler import.
</Note>

## Initialize

```javascript
SouthPay.init({ publishableKey: "sp_pk_live_..." });
```

`init` is required before `createCheckout`. It throws if `publishableKey` is missing, and throws again if the value does not start with `sp_pk_`, so a secret key cannot be used in the browser by mistake.

| Option | Default | Description |
| --- | --- | --- |
| `publishableKey` | — | Required. A publishable key, `sp_pk_live_…` or `sp_pk_test_…` |
| `apiBase` | `https://api.southpay.io` | API base URL. Trailing slashes are stripped |
| `checkoutOrigin` | The origin the script was loaded from | Origin serving the checkout iframe, and the only origin whose messages the SDK accepts |

`mount` does not require `init`. Called on its own it falls back to the script's own origin as the checkout origin.

```javascript
SouthPay.init({
  publishableKey: "sp_pk_test_...",
  apiBase: "http://localhost:3000",
  checkoutOrigin: "http://localhost:5173",
});
```

## Server-created checkout

Create the intent on your server, send the `reference` to the page, then mount it. No key is involved in the browser.

```html
<div id="checkout"></div>
<script src="https://integrate.southpay.io/widgets/v2.js"></script>
<script>
  SouthPay.mount({
    reference: "N2BD0BZJUVH0XGUD",
    container: "#checkout",
    onCompleted: ({ successUrl }) => {
      if (successUrl) window.location.assign(successUrl);
    },
  });
</script>
```

A reference is always 16 uppercase alphanumeric characters.

## Browser-created checkout

`createCheckout` calls `POST /api/v2/payments` with the publishable key, then mounts the resulting checkout for you. It returns the same handle as `mount`.

```javascript
SouthPay.init({ publishableKey: "sp_pk_live_..." });

const handle = await SouthPay.createCheckout({
  amount: 1000,
  currency: "EUR",
  container: "#checkout",
  onStatusChange: ({ status }) => console.log(status),
  onCompleted: ({ reference }) => console.log("paid", reference),
});
```

<Warning>
  `amount` is a **positive integer in minor units**, so `1000` is 10.00 EUR. It is rejected if it is not an integer or is not greater than zero. This differs from the REST API, where `amount` is a decimal string in major units.
</Warning>

Omit `container` on either function to open the checkout as a modal overlay with a close button, instead of inline.

## Options

`mount(options)` returns a handle synchronously. `createCheckout(options)` returns a `Promise` for one.

| Option | Applies to | Type | Description |
| --- | --- | --- | --- |
| `reference` | `mount` | `string` | Required. The payment intent reference to render |
| `amount` | `createCheckout` | `number` | Required. Positive integer, minor units |
| `currency` | `createCheckout` | `string` | Required. ISO fiat code |
| `orderId` | `createCheckout` | `string` | Your order identifier |
| `title` | `createCheckout` | `string` | Shown on checkout |
| `description` | `createCheckout` | `string` | Shown on checkout |
| `imageUrl` | `createCheckout` | `string` | Must be `https` |
| `successUrl` | `createCheckout` | `string` | Passed to the intent, surfaced back on completion |
| `failedUrl` | `createCheckout` | `string` | Passed to the intent |
| `metadata` | `createCheckout` | `object` | Up to 50 keys, all values strings |
| `container` | both | `string \| HTMLElement` | CSS selector or element. Omit for a modal |
| `minHeight` | both | `number` | Minimum iframe height in pixels, default 560 |

The handle is `{ reference, unmount() }`. `unmount()` removes the iframe or overlay and detaches the message listener.

```javascript
const handle = SouthPay.mount({ reference, container: "#checkout" });
handle.unmount();
```

## Events

The checkout iframe posts messages to your page and the SDK turns them into callbacks. All five are optional and can be passed to either function.

| Callback | Payload | Fires when |
| --- | --- | --- |
| `onReady` | none | The checkout has loaded inside the iframe |
| `onStatusChange` | `{ reference, status }` | The payment status changes |
| `onCompleted` | `{ reference, successUrl }` | The payment reaches `completed`. `successUrl` is `null` when the intent has none |
| `onFailed` | `{ reference, status }` | The payment reaches `failed` |
| `onExpired` | `{ reference }` | The intent's 60-minute window elapses without payment |

If you do not supply `onCompleted` and the intent has a `successUrl`, the SDK navigates the top-level page to it. Supplying `onCompleted` suppresses that, and the redirect becomes yours to perform.

The SDK also handles a `resize` message internally to keep the iframe's height matched to its content; there is no callback for it.

`status` is the payment intent status, and there are six: `pending`, `processing`, `completed`, `expired`, `failed`, `refunded`. A live payment moves `pending → processing → completed`. There is no `created` status and no `confirming` status. An overpayment arrives as `completed`; the distinction is carried by `state_reason: "completed_overpaid"` on the intent, which the widget does not surface.

## Errors

The SDK throws plain `Error` objects with a message prefixed by the function that threw. There is no error class and no error code enum to switch on — match on the call site instead.

| Thrown by | When |
| --- | --- |
| `SouthPay.init` | `publishableKey` is missing, or does not start with `sp_pk_` |
| `SouthPay.createCheckout` | Called before `init`; `currency` missing; `amount` not a positive integer; the API returned a non-2xx; the response carried no `reference` |
| `SouthPay.mount` | `reference` is missing |

For an API failure, `createCheckout` reads the message out of the response body, handling both the `{"error": "..."}` and `{"error": {"message": "..."}}` [envelopes](/errors), and falls back to `request failed (<status>)`. A `container` selector that matches nothing does not throw: the checkout opens as a modal instead, which is worth knowing when a typo silently changes your layout.

## Content Security Policy

The widget loads a script, embeds an iframe, and talks to the API from the top-level page:

```text
script-src  https://integrate.southpay.io
frame-src   https://pay.southpay.io
connect-src https://api.southpay.io
```

`connect-src` is only needed for `createCheckout`; a `mount`-only page makes no API calls of its own. Adjust the hosts if you override `apiBase` or `checkoutOrigin`.

## Verify the payment on your server

Southpay derives the payment status from the chain. You read it; you never set it.

`onCompleted` runs in the buyer's browser, so use it for UI only. Before releasing goods, confirm with Southpay:

- handle the [`payment_intent.completed` webhook](/webhooks), or
- re-fetch the intent with your secret key.

```bash
curl https://api.southpay.io/api/v2/payments/{id} \
  -H "Authorization: Bearer sp_sk_live_..."
```

<Warning>
  Never fulfill on the browser callback alone. Any page can call `onCompleted` without a real payment. Southpay marking the intent `completed`, after on-chain confirmation, is the only source of truth.
</Warning>

## How the embed works

Useful when debugging a page that will not render.

The SDK creates an iframe pointed at `{checkoutOrigin}/{reference}?embed=1&origin={your page origin}`, and the checkout only enters embed mode when both the `embed` parameter is present and it is genuinely framed. Messages travel by `postMessage`, targeted at the `origin` value rather than broadcast, and every payload carries `source: "southpay:checkout"`. The SDK drops any message whose origin is not the configured `checkoutOrigin` or whose `source` does not match.

Inside the iframe, checkout polls `GET /api/v2/checkout/{reference}` every 8 seconds and stops once the intent is terminal or has expired. That poll is the only thing driving `onStatusChange`, so events arrive within roughly that interval, not instantly.

## Legacy embed script

An older, smaller shell also ships from the checkout origin:

```html
<script src="https://pay.southpay.io/embed.js"></script>
```

It defines a `Southpay` global with only `Southpay.mount({ container, reference, minHeight })`, and different callback names — `onStatus`, `onSuccess`, `onError`, `onExpire` — returning `{ iframe, destroy() }`. It also auto-mounts any element carrying a `data-southpay-checkout="<reference>"` attribute on page load, with `data-southpay-min-height` as an optional companion.

It cannot create payment intents and takes no key. Prefer SouthPay.js for new integrations; this exists for pages already using it.
