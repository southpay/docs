---
title: "Checkout widget"
description: "Embed SouthPay hosted checkout in your page with the SouthPay.js browser SDK: create intents, mount inline or as a modal, and handle events."
---

SouthPay.js renders SouthPay's hosted checkout inside your page, inline or as a modal. All payment UI (QR code, wallet connect, network picker, status, countdown) lives in an iframe served from the checkout origin, so the script itself is a thin DOM shell with no framework and no dependencies.

It does two things: create a payment intent from the browser with a publishable key, and mount the checkout for a reference you already have.

## Load the script

```html
<script src="https://integrate.southpay.io/widgets/v2.js"></script>
```

The script defines a global `SouthPay`. Read the version it loaded from `SouthPay.VERSION`.

<Note>
  There is no npm package. SouthPay.js ships only as this hosted bundle. Load it with a `<script>` tag rather than a bundler import.
</Note>

## Create a client

`SouthPay` is a factory, not a namespace. Call it with a publishable key to get a client.

```javascript
const southpay = SouthPay("sp_pk_live_...");
```

The key must match `sp_pk_live_...` or `sp_pk_test_...`. Anything else, in particular a secret `sp_` key, throws `invalid_publishable_key` immediately. Publishable keys can only create checkouts, which is what makes them safe to ship to a browser.

A second argument overrides the endpoints:

```javascript
const southpay = SouthPay("sp_pk_test_...", {
  apiBase: "https://api.southpay.io",
  checkoutOrigin: "https://pay.southpay.io",
  nonce: "<your-csp-nonce>",
});
```

<ParamField path="apiBase" type="string" default="https://api.southpay.io">
  Where `paymentIntents.create` posts. Must be a valid `http(s)` URL; trailing slashes are stripped.
</ParamField>

<ParamField path="checkoutOrigin" type="string" default="https://pay.southpay.io">
  Origin the checkout iframe is loaded from, and the only origin whose messages the SDK accepts.
</ParamField>

<ParamField path="nonce" type="string">
  CSP nonce applied to the `<style>` element the SDK injects. Set this if your policy has no `style-src 'unsafe-inline'`.
</ParamField>

## Create a payment intent in the browser

```javascript
const southpay = SouthPay("sp_pk_live_...");

const { reference } = await southpay.paymentIntents.create({
  amount: "49.99",
  currency: "USD",
  orderId: "order_8721",
  successUrl: "https://yourapp.com/success",
  failedUrl: "https://yourapp.com/cancel",
  metadata: { cart_id: "c_991" },
});
```

<ParamField path="amount" type="string" required>
  A positive decimal string in **major** units: `"49.99"`, not `4999`. See [Amount format](#amount-format).
</ParamField>

<ParamField path="currency" type="string" required>
  Fiat currency code. Omitting it throws `missing_currency`.
</ParamField>

<ParamField path="orderId" type="string">
  Your own order identifier, stored on the intent as `order_id`.
</ParamField>

<ParamField path="title" type="string">
  Line title shown on the checkout page.
</ParamField>

<ParamField path="description" type="string">
  Longer description shown under the title.
</ParamField>

<ParamField path="imageUrl" type="string">
  Product image shown on the checkout page.
</ParamField>

<ParamField path="successUrl" type="string">
  Where the buyer lands after a completed payment.
</ParamField>

<ParamField path="failedUrl" type="string">
  Where the buyer lands after a failed or canceled payment.
</ParamField>

<ParamField path="metadata" type="object">
  Arbitrary key/value pairs echoed back on the intent and on webhooks.
</ParamField>

<ParamField path="idempotencyKey" type="string">
  Sent as the `Idempotency-Key` header. If you omit it the SDK generates a UUID per call, so a retry you did not write is a *new* intent. Supply your own to make retries safe. See [Idempotency](/idempotency).
</ParamField>

<ParamField path="timeoutMs" type="number" default="20000">
  Aborts the create request and throws `timeout`.
</ParamField>

<ParamField path="signal" type="AbortSignal">
  Cancel the request yourself. Aborting throws `network_error`.
</ParamField>

The call returns only `{ reference }`. To read the full intent, including addresses, amounts and status, fetch it server-side with a secret key; a publishable key cannot.

## Mount the checkout

```javascript
const handle = southpay.checkout.mount({ reference, container: "#checkout" });
```

<ParamField path="reference" type="string" required>
  The 16-character reference. Missing throws `missing_reference`.
</ParamField>

<ParamField path="container" type="string | Element">
  A CSS selector or element to render into. **Omit it and the checkout opens as a centered modal** with its own overlay and close button.
</ParamField>

<ParamField path="minHeight" type="number" default="560">
  Starting iframe height in pixels, before the checkout reports its own. The SDK caps subsequent resizes at 5000px.
</ParamField>

<Warning>
  Passing a `container` that matches nothing throws `container_not_found`. It does not silently fall back to a modal. Only *omitting* `container` gives you a modal.
</Warning>

`mount` returns a handle:

```javascript
handle.reference;
handle.unmount();
```

`unmount()` removes the iframe, tears down the modal if there is one, and detaches the message listener. Call it when your component unmounts, or the listener outlives the page.

### Inline

```html
<div id="checkout" style="max-width:460px"></div>
<script src="https://integrate.southpay.io/widgets/v2.js"></script>
<script>
  const southpay = SouthPay("sp_pk_live_...");
  southpay.checkout.mount({
    reference: "K4TP9WQZ2XR7HB3M",
    container: "#checkout",
    onCompleted: ({ reference }) => console.log("paid", reference),
  });
</script>
```

### Modal

```javascript
southpay.checkout.mount({
  reference: "K4TP9WQZ2XR7HB3M",
  onExpired: () => showRetry(),
});
```

### Mounting a checkout your server created

The common production shape: create the intent server-side with a secret key so you control pricing, then hand the reference to the browser purely to render.

```javascript
const res = await fetch("/api/checkout", { method: "POST" });
const { reference } = await res.json();

SouthPay("sp_pk_live_...").checkout.mount({ reference, container: "#checkout" });
```

## Events

Pass callbacks to `mount`.

| Callback | Fires when | Receives |
| --- | --- | --- |
| `onReady` | The iframe has loaded and handshaked | Nothing |
| `onStatusChange` | Status changes on-chain | `{ reference, status }` |
| `onCompleted` | Payment completed | `{ reference, successUrl }` |
| `onFailed` | Payment failed | `{ reference, status }` |
| `onExpired` | The 60-minute window elapsed | `{ reference }` |
| `onError` | The widget could not load | `SouthpayError` |

<Warning>
  **If you do not pass `onCompleted`, the SDK navigates the buyer to `successUrl` itself.** Pass `onCompleted` whenever you want to stay on the page. Providing it suppresses the automatic redirect entirely.
</Warning>

`onError` covers loading failures only: the iframe erroring, or no handshake within 20 seconds. Errors from `paymentIntents.create` are thrown, not routed here, so wrap that call in `try/catch`.

Statuses are the six in the [payment lifecycle](/payment-lifecycle). SouthPay derives status from the chain; you read it, you never set it.

<Warning>
  Never fulfill an order on a browser callback alone. Any page can invoke `onCompleted` without a real payment. The only source of truth is the intent reaching `completed` server-side. Confirm with a [webhook](/webhooks) or by fetching the payment with a secret key.
</Warning>

## Amount format

`amount` is a decimal string in major units, and the SDK validates precision against the currency before sending anything.

| Currency | Decimals | Valid |
| --- | --- | --- |
| Most currencies | 2 | `"49.99"` |
| `JPY`, `KRW`, `CLP`, `VND`, `XAF`, `XOF`, and other zero-decimal codes | 0 | `"5000"` |
| `BHD`, `KWD`, `OMR`, `JOD`, `IQD`, `LYD`, `TND` | 3 | `"12.500"` |
| `CLF` | 4 | `"1.2345"` |

Too many decimal places throws `invalid_amount`, as does a zero amount, a negative sign, or a number rather than a string. The SDK pads to the currency's precision, so `"10"` in USD is sent as `"10.00"`.

## Errors

Every SDK failure is a `SouthpayError` carrying a machine-readable `code`.

```javascript
try {
  const { reference } = await southpay.paymentIntents.create({
    amount: "49.99",
    currency: "USD",
  });
} catch (err) {
  if (SouthPay.isSouthpayError(err) && err.code === "invalid_amount") {
    showFieldError(err.message);
  } else {
    throw err;
  }
}
```

`SouthPay.isSouthpayError` is safer than `instanceof` because it also matches errors thrown by a differently-bundled copy of the SDK on the same page.

| Code | Raised by | Cause |
| --- | --- | --- |
| `invalid_publishable_key` | `SouthPay()` | Key missing, or not `sp_pk_live_` / `sp_pk_test_` |
| `invalid_config` | `SouthPay()` | `apiBase` or `checkoutOrigin` is not a valid `http(s)` URL |
| `missing_currency` | `paymentIntents.create` | No `currency` |
| `invalid_amount` | `paymentIntents.create` | Not a decimal string, too many decimals, or zero |
| `request_failed` | `paymentIntents.create` | API returned a non-2xx |
| `invalid_response` | `paymentIntents.create` | 2xx carried no `reference` |
| `network_error` | `paymentIntents.create` | Request failed or was aborted via `signal` |
| `timeout` | `paymentIntents.create` | Exceeded `timeoutMs` |
| `missing_reference` | `checkout.mount` | No `reference` |
| `container_not_found` | `checkout.mount` | `container` matched no element |
| `widget_load_failed` | `onError` | Iframe errored, or no handshake within 20s |

On `request_failed` the SDK unwraps the API's error body for you, handling both the plain-string and structured shapes described in [Errors](/errors), so `err.message` is the API's message rather than a status code.

## Content Security Policy

```text
script-src  https://integrate.southpay.io
frame-src   https://pay.southpay.io
connect-src https://api.southpay.io
```

The SDK injects one `<style>` element. If your policy omits `'unsafe-inline'` for styles, pass `nonce` when you construct the client and the same nonce is applied to that element.

## Legacy embed script

An older, smaller script is still served from the checkout origin:

```html
<script src="https://pay.southpay.io/embed.js"></script>
```

It defines `window.Southpay` (note the lowercase `p`, unlike the `SouthPay` global above) with a single method:

```javascript
const handle = Southpay.mount({
  reference: "K4TP9WQZ2XR7HB3M",
  container: "#checkout",
  minHeight: 560,
  onStatus: ({ status }) => {},
  onSuccess: () => {},
  onExpire: () => {},
  onError: () => {},
});

handle.iframe;
handle.destroy();
```

It also auto-mounts on page load: any element carrying `data-southpay-checkout="<reference>"` is mounted automatically, with `data-southpay-min-height` as an optional companion, and is marked `data-southpay-mounted` once done. `Southpay.checkoutOrigin` exposes the origin it talks to.

It cannot create payment intents, takes no key, and uses different callback names. Prefer SouthPay.js for new integrations; this exists for pages already built on it.
